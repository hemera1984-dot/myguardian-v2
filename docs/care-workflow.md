# 케어센터 발행 공정 — 일간·주간·월간 안창민

v1 careRouter의 실제 생성 로직을 계승하되, 인앱 AI 대신 Code 세션(Claude)이 생산 엔진이다.
발행물은 정적 파일로 저장되고, 발송은 카톡 문구 복사 → 수동 전송이다(v1 실운영 방식 그대로).

## 발행 일정

| 채널 | 발행 | 분량 | 작성 시점 |
|---|---|---|---|
| 일간 안창민 | 매일 | **한 꼭지 700~1,200자** | 당일 |
| 주간 안창민 | 매주 월요일 | 4꼭지 | 일요일 또는 월요일 오전 |
| 월간 안창민 | 매월 첫째 주 월요일 | 3칼럼 | 전주 일요일 ~ 당일 오전 |

일간은 인사말을 붙이지 않고 바로 본론으로 간다 — 매일 붙이면 금방 상투가 된다.
꼭지 주제는 자유이며 카테고리는 쓰고 나면 자동으로 붙는다. 주간만 보험·자산·세무를
기본으로 잡아 일간과의 재탕을 줄인다(2026-08-17).

발송: 고객에게 카톡으로 링크 + 문구 전송.

## 발행 공정 도구 (2026-07-19 신설 — 1차 하이브리드)

발행 데스크(web/care/desk.html)가 공정의 시작과 끝이다. 케어센터는 사이드바 워크스페이스
(발행 데스크 / 서재 / 마이가디언 홈)로 재편되었다.

공정의 주도권은 가제에 있다. 발행인이 이미 아는 주제로 가제를 쓰면, 집필 세션이 제목을
다듬고 근거를 수집해 기사를 완성한다. 뉴스 후보 목록은 참조용 보조다.

| 단계 | 도구 | 설명 |
|---|---|---|
| 기획 | 발행 데스크 화면 | 채널 선택(**일간 1꼭지**/주간 4꼭지/월간 3칼럼) → 꼭지별 가제 입력(브라우저 저장) → 참조 기사 선택(선택사항) → "집필 지시문 복사" |
| 뼈대 | `python pipeline/new_care_issue.py --channel 주간` | 채번·발행일·주차라벨 자동, 본문 뼈대 생성, issues.json에 상태:초안 등록. 지시문이 초안 id를 자동으로 물고 간다. **일간(`daily-`)은 아직 이 스크립트가 받지 않는다** — 데스크에서만 만든다(2026-08-17 확인) |
| 집필 | 발행 세션 (Code) | 지시문 붙여넣기 → 제목 확정, `collect_news.py --query "키워드"`(뉴스+백과사전)와 웹검색으로 근거 교차 수집, 아래 2~3단계 원칙으로 기사·코멘트 작성. 초안은 리더(issue.html?id=)에서 검토 |
| 발행 | `python pipeline/publish_care_issue.py --id weekly-NN` | 검증(제목·부제·본문·요약·편집장의말·이미지 존재) 통과 시 발행 전환 + 꼭지·요약 동기화 |
| 보조 수집 | `python pipeline/collect_news.py` | 카테고리별 후보 일괄 수집 → 데스크 뉴스 후보 표시 (선택사항). 키는 pipeline/naver-keys.json (gitignore, NAVER API HUB) |

- 초안(상태:초안)은 발행 데스크에만 표시된다. 서재·홈·최신호·카톡 문구에서 제외.
- 2차 공사(Cloudflare Workers) 때 수집·집필이 화면 안 버튼으로 이동한다. 스키마·공정은 그대로.

## 공정 5단계 (Code 세션에서 진행)

### 1단계 — 주제
- "주간 12호 만들자"로 시작하면 AI가 웹 검색으로 최신 이슈를 훑고 주제 3개를 제안한다.
- 카테고리: 건강 / 시장 / 세금 / 보장 / 경제뉴스 (v1 careTopicHistory 5종 계승)
- 직접 주제를 정해도 된다. 제목은 AI 추천을 받거나, 직접 쓴 제목을 AI가 다듬는다.

### 2단계 — 초안 (2단계 생성, v1 계승)
1. 뉴스 수집: AI가 웹 검색으로 해당 주제의 최신 뉴스·수치를 수집한다. (v1은 LLM 웹검색 — 동일. 네이버 오픈API 키가 준비되면 수집원으로 추가 가능)
   - **깊이가 필요한 꼭지는 `/insane-research {주제}`로 돌린다** (2026-08-17 신설). 인라인 인용을
     강제하고 핵심 주장을 최소 2개 독립 소스로 교차검증한 뒤 A–E 등급을 매겨 준다.
     산출물은 `RESEARCH/{topic}_{timestamp}/` 아래에 쌓인다.
   - `collect_news.py`를 대체하지 않는다. 저건 **후보 목록**이고 이건 **근거 조사**다.
     이미지 후보 수집(`--source image`)은 계속 `collect_news.py`가 맡는다.

2. 심층 작성: 수집된 근거로만 본문을 쓴다.

**리서치는 채널마다 다르게 건다** — 한 번 돌리면 에이전트 3~5개가 병렬로 붙는 무거운 공정이다.
분량에 맞지 않으면 배보다 배꼽이 커진다.

| 채널 | 기본 | 언제 돌리나 |
|---|---|---|
| **일간** (한 꼭지 700~1,200자) | **안 돌린다** | 제도·세법·약관이 실제로 바뀐 날, 또는 수치가 근거를 요구할 때만. 매일 돌리면 같은 주제를 매번 새로 조사하게 되고, 재탕을 줄이려 만든 채널 구분이 무너진다 |
| **주간** (4꼭지) | 꼭지별로 판단 | 4꼭지 중 **무거운 1~2개만.** 나머지는 `collect_news.py` + 웹검색 |
| **월간** (3칼럼) | **돌린다** | 칼럼이 길고 한 달을 버텨야 하므로 교차검증이 값을 한다 |

짧은 글일수록 근거 하나가 틀렸을 때 도망갈 자리가 없다. **일간에서 리서치를 건너뛴다는 것은
근거를 덜 본다는 뜻이 아니라, 그날 확인 가능한 것만 쓴다는 뜻이다.** 확인이 안 되면 그 주제를
그날 쓰지 않는다.

**리서치 결과는 그대로 지면에 들어가지 않는다** (2026-08-17). 리포트는 보고서 문체이고
케어 지면은 잡지다. 아래 검문을 통과한 **사실과 수치만** 가져오고, 문장은 다시 쓴다.
검문 항목은 새로 만든 규칙이 아니라 **이 파일과 CLAUDE.md에 이미 있는 것들**이다.

| 리서치가 준 것 | 어떻게 하는가 |
|---|---|
| 정부·공공기관 발표문, 법령, 공식 통계 | 1차 근거로 쓴다 |
| 언론 보도 | 수치만 취하고 문장은 다시 쓴다. 매체명·날짜 표기 |
| 블로그·정리글·소셜미디어 (대개 D·E) | 쓰지 않는다. 「임의로 지어내지 않는다」의 반대편이 「아무거나 근거로 삼지 않는다」다 |
| "이렇게 하세요" 류 조언·추천 문장 | **버린다.** 투자 조언 금지 |
| 판례·분쟁 사례 | **버린다.** 판례는 `data/` 실데이터에서만 나온다. 사건번호 없으면 표시하지 않는다 |
| 보도사진·기사 그래픽 주소 | **버린다.** 통신사·언론사 사진은 AI 변형해도 금지 |

**A–E 등급은 출처의 권위만 재고 시점을 안 잰다.** 세법·제도·보험 약관은 개정이 잦다.
채택한 근거마다 **발표일·시행일·적용 기간**을 확인한다. 확인이 안 되면 쓰지 않는다.

**국내 1차 출처는 약하게 잡힌다** — 내장 웹검색이 미국 중심이라 기재부·국세청·금감원이
잘 안 올라온다. 리서치가 안 물어 왔다고 없는 것이 아니다. 국내 기관 자료는
`collect_law.py`·`collect_fss.py`와 브라우저로 직접 확인한다.

v1 작성 원칙 계승 (careRouter 원문 기준):
- 검색된 뉴스를 반드시 기반으로. 임의로 지어내지 않는다.
- 팩트 나열이 아니라 "그래서 어떻게 될 것 같은지" 전망·분석 포함.
- 경제 이슈는 실생활·자산·보험과의 연관성을 자연스럽게.
- 소제목 3~5개, 소제목당 2~3단락. 전문용어는 괄호로 풀어서.
- 정치적 중립. 투자 조언("이렇게 하세요") 금지 — 분석과 전망 중심.
- "안녕하세요" 인사 금지, 본론부터. AI 티·이모지 금지. 실제 수치·통계 필수.
- 구조: 제목(수치 포함 팩트형) → 부제(시사점 한 줄) → 소제목별 본문 → 종합 전망/정리.

### 3단계 — 코멘트·다듬기
- 마지막에 "안창민 코멘트" 단락: 설계사가 직접 쓴 것 같은 말투로 AI가 작성 (v1 페르소나 방식).
- 수정 지시는 대화로. 반영된 수정 패턴은 다음 호 작성에 참고한다.

### 4단계 — 이미지
- 사진이 없으면 지면이 허전하다. 표지 1장 + 기사마다 1장을 기본으로 한다.
- 후보 찾기: `python pipeline/collect_news.py --query "키워드" --source image`
  (큰 이미지만 걸러 나오며, 원본 주소·크기를 함께 준다)
- 직접 찍은 사진이나 AI 생성 이미지도 쓸 수 있다.
- **고르는 기준**: 출처가 분명할 것. 통신사 워터마크가 박힌 사진은 쓰지 않는다 —
  고객에게 발송하는 발행물이므로 이용 허락이 불분명한 사진은 피한다.
- 파일은 data/care/issues/<id>/ 하위에 두고 표지는 메타의 커버이미지,
  기사 사진은 각 기사의 이미지 경로에 기록한다.

### 5단계 — 발행·발송
1. 본문을 data/care/issues/<id>.json 구조 데이터로 저장 (뼈대는 new_care_issue.py가 생성)
2. data/care/issues.json 메타의 상태를 publish_care_issue.py 검증으로 발행 전환
3. commit & push → GitHub Pages 반영
4. 케어센터 아카이브에서 "카톡 문구 복사" → 카톡에 붙여넣어 발송

카톡 문구 규격 (v1 계승): 4~5줄, {{customerName}} 치환 가능, 마지막 줄에 열람 링크.

## 팀원 발행 — 주간 OOO / 월간 OOO

케어센터는 발행 플랫폼이다. 팀원 누구나 자기 이름의 잡지를 발행할 수 있다.

- 편집장 원칙: 편집장은 항상 안창민이다. 어떤 발행인의 호든 표지·판권에 "편집장 안창민 FC"가 명기되고, 팀원 호에는 "발행 OOO FC"가 병기된다. 편집장의 말 서명도 항상 안창민이다.

- 발행물 메타의 `발행인` 필드에 이름을 넣으면 제호(주간 OOO)·킥커·한마디 라벨·판권·카톡 문구가 전부 그 이름으로 표시된다.
- id 규칙: 안창민 호는 `weekly-12`, 팀원 호는 발행인 식별자를 끼운 `weekly-kse-01` 형식 (충돌 방지).
- 카톡 서명(이름·소속)은 서재 화면 상단 설정에서 각자 자기 브라우저에 저장한다.
- 서재에는 모든 발행인의 호가 함께 꽂히며, 발행인이 2명 이상이 되면 발행인 필터가 자동으로 나타난다.
- 발행 공정은 동일: 각자 Code 세션에서 1~5단계를 진행하고 commit·push 한다.
